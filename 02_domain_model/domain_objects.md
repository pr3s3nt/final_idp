# Step 2: Domain Objects

Tài liệu này mô tả domain model được rút ra từ các bảng **Dữ liệu chính**, business rules của UC-01 đến UC-04 và các main-flow sequence diagram. Model chỉ chứa business entity, value object, generated artifact và execution-time data holder; không chứa Boundary, Controller, Service, Validator, Resolver, Generator, Adapter hay Repository.

Các aggregate root chính là **Application Definition**, **Environment Configuration**, **Deployment**, **Resource Instance** và **Workload Instance**. `Resource Definition` là dữ liệu catalog độc lập do platform quản lý; `Application Specification` là artifact được sinh từ `Application Definition`.

| Domain Object | Thuộc tính chính | Mô tả | Aggregate nó thuộc về |
|---|---|---|---|
| Application Definition | `applicationId`, `name`, `description`, `createdAt`, `updatedAt` | Identity của application; sở hữu các phiên bản định nghĩa. Nội dung cấu trúc logic (workload, resource, dependency, configuration requirement) nằm trong từng Application Definition Version. | **Application Definition** (aggregate root) |
| Application Definition Version | `versionId`, `versionNumber`, `createdAt` | Một phiên bản **bất biến** của cấu trúc logic, được tạo mỗi lần Developer lưu ở UC-01; không bao giờ bị sửa hay xóa. UC-03 deploy đúng một phiên bản vào một environment. | Application Definition |
| Workload | `workloadId`, `name`, `type`, `imageRepository`, `port`, `exposedOutputs` | Một workload trong một phiên bản. `workloadId` là **ID cố định qua các phiên bản** (đổi tên vẫn giữ ID). Chỉ giữ image repository; image tag/version cụ thể thuộc deployment. `exposedOutputs` là các output logic có thể được tham chiếu, ví dụ `endpoint`. | Application Definition (qua Application Definition Version) |
| Resource Requirement | `resourceRequirementId`, `name`, `resourceType` | Nhu cầu resource ở mức logic trong một phiên bản, ví dụ PostgreSQL hoặc Redis; không chứa cách provision. `resourceRequirementId` cố định qua các phiên bản và là một phần của khóa chủ sở hữu Resource Instance. | Application Definition (qua Application Definition Version) |
| Environment Variable Definition | `variableDefinitionId`, `name`, `required` | Khai báo một Environment Variable mà workload cần, chưa có giá trị theo environment. ID cố định qua các phiên bản. | Application Definition (qua Workload) |
| Secret Definition | `secretDefinitionId`, `name`, `required` | Khai báo một Secret mà workload cần và phân biệt nó với Environment Variable thông thường. ID cố định qua các phiên bản. | Application Definition (qua Workload) |
| Dependency | `dependencyId`, `sourceWorkloadId`, `targetType`, `targetId` | Quan hệ `depends on` trong một phiên bản, từ một workload tới đúng một workload hoặc Resource Requirement khác (tham chiếu ID cố định). Quyết định thứ tự triển khai và giới hạn output được tham chiếu. | Application Definition (qua Application Definition Version) |
| Application Specification | `specificationId`, `applicationId`, `format`, `content`, `version`, `updatedAt` | Generated artifact, ví dụ `score.yaml`, được sinh/cập nhật từ một Application Definition Version. | Application Definition (generated artifact) |
| Environment Configuration | `environmentConfigurationId`, `applicationId`, `environment`, `createdAt`, `updatedAt` | Cấu hình của một application cho đúng một environment (`STAGING` hoặc `PRODUCTION`); không có phiên bản, được kiểm tra khớp với phiên bản Application Definition khi lưu (phiên bản mới nhất) và khi deploy (phiên bản được deploy). Thay đổi object này không tự động thay đổi deployment đang chạy. | **Environment Configuration** (aggregate root) |
| Environment Variable | `environmentVariableId`, `workloadId`, `variableName` | Binding theo environment cho một Environment Variable Definition của workload. Giá trị nằm trong một `Configuration Value`. | Environment Configuration |
| Secret | `secretId`, `workloadId`, `secretName`, `secretReference` | Binding theo environment cho một Secret Definition. Khi Developer nhập secret trực tiếp, object chỉ giữ reference do Secret Store trả về; không giữ plaintext. Với sensitive resource output, source được biểu diễn bằng `Resource Output Reference`. | Environment Configuration |
| Configuration Value | `valueSourceType` | Abstract value object biểu diễn nguồn của configuration: direct value, Resource Output Reference hoặc Workload Output Reference. | Environment Configuration |
| Direct Configuration Value | `value` | Giá trị trực tiếp của Environment Variable thông thường. Không được dùng để persist plaintext Secret. | Environment Configuration |
| Resource Output Reference | `resourceRequirementId`, `outputName` | Reference bền vững (qua ID cố định) tới output logic của một Resource Requirement mà workload sở hữu biến depends on, ví dụ `postgresql.host`; giá trị thực chỉ được resolve khi deploy. | Environment Configuration |
| Workload Output Reference | `workloadId`, `outputName` | Reference bền vững (qua ID cố định) tới output logic của một workload mà workload sở hữu biến depends on, ví dụ `backend.endpoint`; giá trị được đọc từ workload đã healthy trong deployment hoặc từ bản đang chạy. | Environment Configuration |
| Resource Definition | `resourceDefinitionId`, `name`, `resourceType`, `provisionerReference`, `supportedContexts`, `defaultParameters`, `allowedOverrides`, `exposedOutputs`, `sensitiveOutputs`, `managementMode`, `applicabilityConditions`, `existingResourceReference` | Định nghĩa do platform cung cấp để map logical Resource Requirement sang provisioner phù hợp theo deployment context. `defaultParameters` giữ giá trị mặc định/schema provisioning để plan resolve parameter theo context; `allowedOverrides` giữ policy gồm các parameter key Developer được phép override cùng tập giá trị, khoảng min-max hoặc enum hợp lệ. Definition đồng thời công bố normal/sensitive outputs hợp lệ. `managementMode = MANAGED` nghĩa là IDP tạo/sửa/hủy hạ tầng; `managementMode = EXISTING` nghĩa là definition trỏ tới resource dùng chung có sẵn (`existingResourceReference`), áp dụng cho application/environment khớp `applicabilityConditions`, và IDP chỉ đọc output. | Platform Resource Definition catalog (độc lập) |
| Deployment | `deploymentId`, `applicationId`, `applicationDefinitionVersionId`, `environment`, `deploymentTarget`, `planFingerprint`, `planFingerprintAlgo`, `status`, `createdAt`, `updatedAt` | Một lần triển khai **một phiên bản** Application Definition vào một environment (`STAGING`/`PRODUCTION`) và target. Đây là lifecycle aggregate giữ context, actual workload images, job và record theo dõi. `status` nhận `AWAITING_CONFIRMATION`, `CONFIRMED`, `DEPLOYING`, `SUCCEEDED`, `FAILED`, do IDP tự quyết, không lấy từ CD. Infrastructure Plan vẫn là `TRANSIENT`; chỉ fingerprint và phiên bản thuật toán của nó được persist để kiểm tra plan rebuild khi confirm. | **Deployment** (aggregate root) |
| Workload Deployment | `workloadDeploymentId`, `workloadId`, `imageRepository`, `imageVersion`, `inclusionReason`, `waveNumber` | Snapshot image thực tế của một workload trong deployment. `imageVersion` được Developer chọn hoặc CI cung cấp tại thời điểm deploy; với workload được tự động deploy lại (`inclusionReason = CASCADED`) là image đang chạy. `waveNumber` là tầng mà workload được triển khai. | Deployment |
| Deployment Execution Job | `jobId`, `selectedOverrides`, `status`, `createdAt`, `updatedAt` | Job triển khai được tạo **cùng transaction** với việc chuyển Deployment sang `CONFIRMED`, giữ giá trị override Developer đã chọn; Deployment Worker lấy job để chạy nền. Tập giá trị `status` và cơ chế phục hồi khi worker chết chưa chốt (D6). | Deployment |
| Deployment Context | `cloudProvider`, `region`, `targetSpecificInput` | Context dùng để resolve Resource Definition và thực hiện target-specific adaptation cho deployment target đã chọn. | Deployment |
| Deployment Graph | `deploymentId`, `workloadIds`, `resourceRequirementIds`, `dependencyIds`, `configurationReferenceIds`, `scopeComponentIds`, `waves`, `potentialRedeployComponentIds` | Dependency/resource graph được dựng từ phiên bản Application Definition, Environment Configuration, workload images và Deployment Context cho một execution; gồm phạm vi deployment (workload được chọn và resource chúng depends on trực tiếp), các tầng theo thứ tự phụ thuộc và danh sách thành phần có thể bị deploy lại khi output thay đổi. | Deployment (execution-scoped) |
| Resource Resolution | `resourceRequirementId`, `resourceDefinitionId`, `resolutionStatus`, `reason` | Kết quả chọn Resource Definition phù hợp cho một logical Resource Requirement; có thể dẫn tới create, update hoặc reuse Resource Instance. | Deployment (execution-scoped) |
| Resource Instance | `resourceInstanceId`, `applicationId`, `environment`, `resourceRequirementId`, `resourceDefinitionId`, `deploymentTarget`, `infrastructureReference`, `providerStateReference`, `status`, `outputFingerprint`, `createdAt`, `updatedAt` | Đại diện durable cho infrastructure đã provision/reconcile, thuộc về **đúng một chủ**: application + environment + resource requirement + deployment target. Chỉ được dùng lại khi khớp đủ bộ này. Nếu Resource Definition là `EXISTING`, instance chỉ liên kết tới resource dùng chung (nhiều instance có thể trỏ cùng `infrastructureReference`) và không đụng hạ tầng thật. `status`: `PLANNED`, `PROVISIONING`, `READY`, `FAILED`, `DESTROYED`, `UNLINKED`. `outputFingerprint` là hash output lần gần nhất, dùng để phát hiện output thay đổi. | **Resource Instance** (aggregate root) |
| Resource Output | `resourceInstanceId`, `outputName`, `resolvedValue`, `sensitive` | Runtime output được collector nạp từ Resource Instance sau khi resource sẵn sàng và dùng để resolve configuration trong một deployment. | Resource Instance (runtime view, execution-scoped) |
| Workload Instance | `workloadInstanceId`, `applicationId`, `workloadId`, `environment`, `deploymentTarget`, `currentWorkloadDeploymentId`, `status`, `outputFingerprint`, `createdAt`, `updatedAt` | Trạng thái hiện hành của một workload trên một environment + target: đang chạy workload deployment nào (image, phiên bản), đã healthy chưa và dấu vân tay output. Dùng cho deploy một phần (đọc output của workload phụ thuộc đang chạy), tự động deploy lại khi output đổi (dùng image đang chạy), gỡ workload và UC-04. `status`: `DEPLOYING`, `HEALTHY`, `FAILED`, `REMOVED`. | **Workload Instance** (aggregate root) |
| Workload Output | `workloadInstanceId`, `outputName`, `resolvedValue` | Runtime output của workload được Workload Output Collector đọc sau khi workload healthy (hoặc từ bản đang chạy) để resolve configuration của các tầng sau; cơ chế đọc cụ thể chưa chốt. | Workload Instance (runtime view, execution-scoped) |
| Resolved Configuration | `deploymentId`, `resolvedEnvironmentVariables`, `resolvedSecrets`, `resolvedDependencies` | Snapshot in-memory sau khi direct values và output references đã được resolve cho deployment hiện tại. | Deployment (execution-scoped) |
| Resolved Specification | `deploymentId`, `format`, `workloadImages`, `resolvedDependencies`, `generatedAt` | Resolved application specification chứa image version, configuration và dependency đã resolve; là input cho `score-k8s`. | Deployment (execution-scoped) |
| Deployment Record | `deploymentRecordId`, `environment`, `deploymentTarget`, `infrastructureReferences`, `deliveryReference`, `removedComponents`, `status`, `errorSummary`, `createdAt`, `updatedAt` | Durable record phục vụ deployment history/result, bao gồm target, actual images qua Workload Deployment, infrastructure references, các thành phần đã gỡ/hủy/gỡ liên kết, delivery reference và lỗi tổng quát. Việc tách status khỏi trạng thái CD để lại cho D5. | Deployment |
| Deployment Step | `deploymentStepId`, `sequenceNumber`, `waveNumber`, `stepName`, `status`, `relatedComponentReference`, `errorSummary`, `startedAt`, `completedAt` | Trạng thái/progress của từng bước theo tầng và thành phần; giữ failed step và workload/resource liên quan khi deployment thất bại. Ai ghi và ghi lúc nào để lại cho D4. | Deployment (qua Deployment Record) |

## Invariants chính

- Một `Application Definition` có `1..*` Application Definition Version; mỗi phiên bản có `1..*` Workload, `0..*` Resource Requirement và `0..*` Dependency.
- Application Definition Version là bất biến: đã tạo thì không bị sửa hay xóa. Workload, Resource Requirement, Environment Variable Definition và Secret Definition giữ ID cố định qua các phiên bản.
- `Environment Variable Definition` và `Secret Definition` luôn thuộc đúng một Workload.
- Mỗi Dependency có đúng một source Workload và đúng một target: Workload hoặc Resource Requirement. Các Dependency của một phiên bản không tạo thành vòng.
- Một `Environment Configuration` thuộc đúng một Application Definition và một environment (`STAGING` hoặc `PRODUCTION`); mỗi configured Environment Variable có đúng một Configuration Value.
- Resource Output Reference và Workload Output Reference chỉ được trỏ tới thành phần mà workload sở hữu biến depends on.
- Một configured Secret có đúng một source: `secretReference` hoặc sensitive `Resource Output Reference`. Plaintext Secret không thuộc persistent domain model.
- Một `Deployment` deploy đúng một Application Definition Version, có đúng một Deployment Context và `1..*` Workload Deployment; mỗi Workload Deployment ghi image version thực tế. Deploy một phần chỉ dùng phiên bản đang chạy trên environment + target đó.
- Deployment ở `CONFIRMED` luôn có đúng một Deployment Execution Job, được tạo trong cùng transaction.
- Mỗi chủ sở hữu (application + environment + resource requirement + deployment target) có tối đa một Resource Instance đang dùng; mỗi workload + environment + deployment target có tối đa một Workload Instance.
- Resource Output chỉ được dùng sau khi Resource Instance tương ứng đã resolve/reconcile và ở trạng thái sẵn sàng; Workload Output chỉ được dùng sau khi workload tương ứng healthy.
